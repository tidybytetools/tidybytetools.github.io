AI slop in a README: the words and patterns to cut, with plain swaps

A short list of the phrases that make AI-written READMEs and docs sound generic, what to write instead, and the free tools that check for them.

Readers can tell when a README was written on autopilot. Trust drops, and people stop reading. This page lists what to cut and what to write instead. The lists come from the phrase list in our own checker, so you can test every line.

Openers and closers

Cut thisWrite this
Certainly!, Great question, Absolutely!Nothing. Start with the answer.
I hope this helps, Let me know if you have any questionsNothing, or say who to contact and how.
Let's dive in, deep diveNothing, or "look at".
Feel free to reach outThe exact way: an issue link, an email or a channel.

Hype

Cut thisWrite this
blazing fast, lightning fastThe measured time. If you did not measure, say "fast" or nothing.
game-changer, revolutionary, revolutionizeWhat changes, in plain words.
seamless, effortlessWhat the reader does not have to do, or how many steps it takes.
cutting-edge, state-of-the-artThe method or version name, or a benchmark.
world-class, best-in-classDelete it, or show proof.

Fancy words and filler

Cut thisWrite this
delve, leverage, utilize"look at", "use".
embark"start".
tapestry, testament toThe plain fact.
it is important to note that, at the end of the day, in conclusionDelete it. State the fact.
in today's fast-paced world, in the ever-evolvingDelete it. Start with the point.

Patterns, not only words

  • The It's not X, it's Y move. Say what the thing is, once.
  • Em dashes in every sentence. Use a period, a comma or a colon.
  • Emoji at the start of headings and list items.
  • Many exclamation marks.
  • Placeholders left behind, like [Insert ...] or TODO: add.
  • Very long sentences. Split anything over 40 words.

Be specific instead. Name the file, the command, the number and the version.

Check it with a script

Words are easy to miss when you read your own text. A checker finds them with line numbers.

python3 slop_check.py README.md

Our Anti-Slop Kit ($9) has slop_check.py: standard library Python, no AI, about 150 phrases and 10 pattern checks. It skips code blocks, inline code and URLs. It is not an AI detector. It checks words and patterns in English, and cannot tell whether your docs are true.

Free options

Several free projects help here, and some are good:

  • Anti-Slop Rules (ours): 12 plain-writing rules, a Cursor rule and a de-slop skill. Instructions only.
  • anti-ai-slop-writing: a skill with a banned-words file.
  • anti-ai-slop: a skill that removes AI-writing patterns and then checks the result.
  • no-ai-slop: a set of anti-slop rules and word lists.

Try a free one first. If rules alone keep working for you, you do not need a checker. If agents write your docs every day and you want the rules enforced on every commit and pull request, that is what the Anti-Slop Kit adds: the checker, a Claude Code hook, a git hook and a GitHub Action.
